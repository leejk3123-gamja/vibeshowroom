# 🏛 바이브 벤처 웹 전시관 (v4)

구글 시트 한 장으로 운영하는 학생 작품 전시관입니다.
**매달 시트에 탭 하나만 추가**하면 전시실이 늘어나고, 스크린샷은 GitHub Actions가 자동으로 찍어 줍니다.

```
index.html                 화면
css/style.css              디자인 (:root 변수로 테마 변경)
js/config.js               ★ API 주소·문구·옵션 — 보통 이 파일만 수정
js/app.js                  동작
apps-script/Code.gs        구글 시트 Apps Script 에 붙이는 백엔드
scripts/screenshot.mjs     스크린샷 생성기 (Actions 가 실행)
.github/workflows/         매월 자동 스크린샷 워크플로
thumbs/                    생성된 스크린샷 (자동 커밋됨)
```

## 기능
- 월별 전시실 탭 · 카드형 액자에 **실제 앱 스크린샷** 표시
- 카드 3D 틸트, 조명·유리 반사, 스크롤 등장 애니메이션
- 👏 **응원 박수**(브라우저당 작품별 최대 5회) · 💬 **방명록** · 최근 방명록 흐름(티커)
- 🎲 랜덤 관람 · ▶ **슬라이드쇼**(수업·전시용 전체 화면 자동 전환)
- 검색, 정렬(번호/방명록/박수/이름/무작위), 작품별 공유 링크(`#/2026-09/작품명`)
- 키보드 ← → Esc, 모바일 대응, DEMO 모드(API 없이 디자인 확인)

## 설치 (총 5단계)

### 0. 화면 미리 보기
압축을 풀고 `index.html`을 더블클릭 → 샘플 데이터(DEMO)로 전시관이 열립니다.

### 1. 구글 시트 준비
| 탭 이름 | 용도 |
|---|---|
| `6월`, `7월`, `8월` … (또는 `2026년 1월`) | 월별 작품 목록. 비어 있으면 "준비 중"으로 표시 |
| `피드백데이터`, `반응데이터` | 자동 생성됨. 직접 만들 필요 없음 |

작품 탭 열 순서 (1행은 머리글, 2행부터 데이터):

| A | B | C | D | E | F | G | H | I |
|---|---|---|---|---|---|---|---|---|
| 번호 | **프로젝트명** (필수) | **링크** (필수) | 소개 | 개발자 | 학교 | 학년 | 반 | 썸네일 URL (선택) |

- A~D 만 있어도 동작합니다. I 열에 이미지 주소를 넣으면 자동 스크린샷 대신 그 이미지를 씁니다.
- 프로젝트명은 같은 달 안에서 중복되지 않게 해 주세요 (방명록·박수를 연결하는 키입니다).

### 2. Apps Script 붙이기
1. 시트 → **확장 프로그램 → Apps Script**
2. 기존 코드를 지우고 `apps-script/Code.gs` 내용을 붙여넣기 → 💾 저장
3. 연도가 다르면 맨 위 `BASE_YEAR` 수정
4. 함수 드롭다운에서 **`authorize`** 선택 → ▶ 실행 → 권한 승인
5. 실행 로그에 `6월 → 2026-06 / 작품 N개` 같은 줄이 보이면 성공

### 3. 웹 앱 배포
**배포 → 새 배포 → ⚙️ 웹 앱** → 실행 주체 **나**, 액세스 **모든 사용자** → 배포 → URL 복사
(`https://script.google.com/macros/s/…/exec`)

> 확인: `URL?action=ping` 을 브라우저에서 열면 `{"ok":true,...}` 가 보여야 합니다.
> 「모든 사용자」가 없으면 조직 정책 때문이니 개인 구글 계정으로 시트를 공유받아 진행하세요.
> **Code.gs 를 수정할 때마다** 배포 → 배포 관리 → ✏️ → 새 버전 → 배포 를 해야 반영됩니다. URL 은 그대로 유지됩니다.

### 4. config.js 에 URL 넣기
`js/config.js` → `API_URL: 'https://script.google.com/macros/s/…/exec'`

### 5. GitHub 에 올리고 Pages 켜기
1. GitHub 에서 새 저장소(Public) 만들기 → 이 폴더의 **모든 파일**(숨김 폴더 `.github`, `.nojekyll` 포함) 업로드
2. **Settings → Pages → Branch: main / (root) → Save** → 몇 분 후 `https://아이디.github.io/저장소명` 발급
3. **Settings → Actions → General → Workflow permissions → "Read and write permissions"** 체크 → Save
   (스크린샷을 저장소에 커밋하기 위해 필요)
4. **Actions 탭 → "작품 스크린샷 생성" → Run workflow** → 2~5분 후 `thumbs/` 폴더에 이미지가 생기고 페이지에 반영됩니다

## 매달 업데이트 절차
1. 시트에 새 탭 추가 (예: `10월`) → 작품 행 입력
2. (선택) GitHub → Actions → "작품 스크린샷 생성" → Run workflow
   - 안 해도 매월 2일 자동 실행되고, 그 전에는 실시간 미리보기(mShots)로 대체 표시됩니다
3. 끝. 코드 수정·재배포 없음

## 스크린샷 관련 메모
- 저장된 스크린샷이 없으면 `LIVE_SHOT` 서비스(기본 mShots)가 실시간으로 찍어 보여 줍니다. **첫 요청은 "생성 중" 이미지**가 나올 수 있고 잠시 후 새로고침하면 실제 화면이 나옵니다.
- 로그인이 필요한 앱은 로그인 화면이 찍힙니다. 이런 작품은 시트 I 열에 직접 캡처한 이미지 주소(GitHub 에 올린 파일 주소 등)를 넣어 주세요.
- 특정 작품만 다시 찍기: Run workflow 에서 `month` 에 `2026-09` 입력, `force` 체크.

## 자주 묻는 문제
| 증상 | 원인 / 해결 |
|---|---|
| 계속 DEMO 화면 | `config.js` 의 `API_URL` 이 비어 있음 |
| "전시 데이터를 불러오지 못했습니다" | 배포 액세스가 「모든 사용자」가 아님, 또는 새 버전 배포를 안 함 |
| 시트를 고쳤는데 반영이 안 됨 | 최대 2분 캐시. 즉시 반영은 Apps Script 에서 `clearCache` 실행 |
| 방명록/박수가 저장 안 됨 | 작품명이 시트와 다르거나(공백 포함), 배포가 구버전 |
| Actions 가 push 실패 | Settings → Actions → Workflow permissions 를 Read and write 로 |
| 카드 이미지가 회색 "생성 중" | mShots 첫 요청. 잠시 후 새로고침, 또는 Actions 로 스크린샷 생성 |

## 디자인 바꾸기
`css/style.css` 맨 위 `:root` 의 `--gold`(포인트색), `--bg`(벽 색), `--serif`(제목 폰트)만 바꿔도 분위기가 달라집니다.
